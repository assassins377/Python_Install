# Windows: исследование и незавершённая проверка совместимости

Дата исследования: 10 октября 2026 года. **Совместимость прототипа с Windows
7/8/8.1/10/11 пока не подтверждена испытаниями этих клиентских ОС.**
Компиляция x86/x64 и CI на Windows Server 2022 — отдельный уровень доказательств.

## Зафиксированный кандидат

| Компонент | Решение для первого прототипа | Ограничение |
| --- | --- | --- |
| Язык | C++17 | Стандарт языка не задаёт минимальную Windows |
| MSVC | v142, toolset 14.29.30133, установленный в VS 2022 | Проверить конкретную версию `cl` и runtime из артефакта; обновление toolset требует повторных испытаний |
| SDK | 10.0.19041.0 | Заголовки SDK не гарантируют, что импортируемая функция существует на старой ОС |
| WinAPI | `WINVER`/`_WIN32_WINNT=0x0601`, Unicode API | Это ограничение объявлений для Windows 7, не исправление несовместимых библиотек |
| CRT/STL | `/MT` Release, `/MTd` Debug; одинаково для приложения и wxWidgets | Статическая линковка исключает установку VC Redistributable как отдельного шага, но сохраняет зависимости от Windows и требует пересборки при исправлениях CRT |
| wxWidgets | 3.2.11, статическая Unicode-сборка из исходников | Сохраняем кандидата из плана; обновление до 3.2.12 или иной версии — отдельное решение и повторные тесты |
| JSON | nlohmann/json 3.12.0 | Header-only; поведение путей/потоков определяется STL и CRT |
| Сборочная система | CMake 3.31.6 в CI, Ninja на Linux, VS generator на Windows | CMake, GitHub runner и IDE работают на современной машине, не входят в пакет приложения |
| Артефакты | Отдельные x86 и x64 EXE, каталог, схема, лицензии, PE-отчёты, SHA-256 | Полноценной миграции стабильного EXE/самообновления пока нет |

## Что проверено по первичным источникам

1. Документация **самого wxWidgets 3.2.11** перечисляет Windows 7/8/10/11 и
   32/64-битные сборки. Это утверждение о библиотеке, не о нашем пакете.
   [Исходник install.md на закреплённом коммите](https://github.com/wxWidgets/wxWidgets/blob/749625e0ea4d70d1f75494aa52231d835531a618/docs/msw/install.md).
   Использование C++17 повышает требования к компилятору относительно минимума wxWidgets.
2. Microsoft перечисляет Windows 7 и Windows 8/8.1 среди целей обычных desktop-
   приложений VS 2019. Поэтому v142 выбран **кандидатом** для эксперимента;
   это не гарантия любой комбинации SDK, STL, зависимостей и опций.
   [VS 2019 compatibility](https://learn.microsoft.com/en-us/visualstudio/releases/2019/compatibility).
3. Современный VC v14 Redistributable, описанный Microsoft, поддерживает Windows
   10/11 и соответствующие Server. Нельзя автоматически использовать `latest`
   Redistributable в пакете для Windows 7/8. При переходе на `/MD` нужно отдельно
   выбрать подходящие runtime/UCRT, способ доставки и обязательные обновления ОС.
   [VC Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist),
   [UCRT deployment](https://learn.microsoft.com/en-us/cpp/windows/universal-crt-deployment).
4. Microsoft описывает `WINVER`/`_WIN32_WINNT` как выбор доступных объявлений API.
   Эти определения не меняют импорты заранее собранной DLL или реализацию STL.
   [WINVER и _WIN32_WINNT](https://learn.microsoft.com/en-us/cpp/porting/modifying-winver-and-win32-winnt).

Прототип использует `std::filesystem` (проверка файлов, Unicode-пути, потоки),
контейнеры и исключения. Именно их реализацию из выбранного toolset нужно
проверить на минимальной ОС. Не добавлять C++20 synchronization/новые WinAPI
или библиотеки из случайного MinGW/MSYS2 дистрибутива без проверки минимальной
ОС и CRT. Смесь MinGW и MSVC C++ ABI недопустима. Если выбранный MSVC-кандидат
не проходит VM, сначала разобрать загрузчик/импорты и зависимости; не объявлять
проблему решённой одним `_WIN32_WINNT` или `/MT`.

Отключены wxWebView, wxWebRequest, media, STC и другие ненужные прототипу
подсистемы. Полная проверка HTTPS, сертификатов, TLS, UAC и запуска процессов
пока невозможна: эти функции ещё не реализованы.

## Матрица испытаний готового пакета

| Целевая ОС | Архитектура EXE | Статус |
| --- | --- | --- |
| Windows 7 SP1 x86/x64 | x86 на x86; x64 и отдельно x86/WOW64 на x64 | Не испытано |
| Windows 8.0 x86/x64 | x86 на x86; x64 и отдельно x86/WOW64 на x64 | Не испытано |
| Windows 8.1 x86/x64 | x86 на x86; x64 и отдельно x86/WOW64 на x64 | Не испытано |
| Windows 10, указать build/редакцию | x86/x64 на соответствующих системах | Не испытано |
| Windows 11, указать build/редакцию | x64; отдельно x86/WOW64 | Не испытано |
| GitHub `windows-2022` | x86/x64 | Автоматическая сборка, CTest и smoke; результаты конкретного PR в Actions |

Перед заявлением о поддержке каждой ОС:

1. Восстановить чистую VM без Python/IDE. Зафиксировать ОС, разрядность, build,
   SP/KB, установленные CRT, SHA коммита и SHA-256 исполняемого файла.
2. Проверить `pe-headers.txt` (архитектура/subsystem) и `pe-imports.txt`.
   Сопоставить обычные и delay-load импорты с целевой ОС, включая зависимости
   DLL. Отсутствие подозрительного импорта не заменяет запуск.
3. Распаковать пакет в каталог с пробелами и кириллицей. Запустить `--version`,
   `--list`, `--list --catalog ...`, проверить UTF-8 перенаправление и код 0.
   Запускать из другого рабочего каталога.
4. Открыть GUI, выбрать категории/программы, проверить текст, клавиатуру, DPI,
   закрытие; выполнить `--gui-smoke`. Убедиться, что нет скачивания/установки
   и запросов UAC.
5. Проверить отсутствующий/повреждённый каталог, неверный тип поля, неизвестную
   версию, превышение размера; CLI должен вернуть 3 без частичного результата.
6. Сохранить отчёт с фактическими результатами, диагностикой загрузчика,
   необходимыми KB/CRT и снимком GUI. Windows 8.1 не заменяет тест Windows 8.0.

Старые VM не подключаются как постоянные runner с секретами для недоверенных
PR. Если нужной VM нет, соответствующая строка остаётся «не испытано».
Это PR с прототипом, а не завершение этапа доказательства совместимости из плана.
