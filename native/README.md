# MInstAll Native — первый прототип

Изолированный перенос на **C++17 + wxWidgets 3.2.11**, версия прототипа **0.1.0**.
Источник контрактов — Python v2.2.2 (`915dfcc7f454`) и существующий
`programs.schema.json`. Учтён документ `MInstAll_CPP_wxWidgets_Migration_Plan.docx`
от 10 октября 2026 года: независимое ядро, постепенный перенос, отдельные сборки,
сохранение Python и проверка готовых бинарников до заявления о совместимости.

## Что работает

- CMake/CTest, отдельное ядро без wxWidgets и окно с деревом категорий/программ.
- Чтение существующего UTF-8 `programs.json`, сохранение порядка и всех полей
  записей, включая неизвестные расширения. Выбор программы показывает название,
  версию и описание обычным текстом. Если версия или описание отсутствует, это
  явно указано. Команды, пути значков и внутренние поля JSON в панели не выводятся;
  URL не открываются, значки не загружаются.
- `--version`, `--list`, `--help`, `--catalog FILE`.
- Проверки формата, повреждённых файлов, Unicode-путей, CLI и цикла открытия/
  закрытия GUI. Отдельные Windows x86/x64 пакеты в артефактах PR.

Нет исполнения `cmd`, `pre_cmd`, `post_cmd`, `uninstall_cmd`, установки,
скачивания, повышения прав, обнаружения ПО, обновления, записи профилей или
состояния. Стабильные Python-файлы, `build.yml`, `release.yml`, `version.json`
и релиз v2.2.2 не изменяются. Прототип не заменяет `MInstAll_x86.exe`/
`MInstAll_x64.exe`; его имя — `minstall-native.exe`.

## Сборка Windows

На современной машине сборки установите Visual Studio 2022 с компонентами
MSVC v142 x86/x64 **14.29.30133** и Windows SDK **10.0.19041.0**, CMake **3.31.6**.
Presets намеренно требуют этот toolset: при его отсутствии следует установить
его, а не незаметно переключаться на последний компилятор.

Из каталога `native/`:

```powershell
cmake --preset windows-x86
cmake --build --preset windows-x86 --parallel 2
ctest --preset windows-x86
cmake --install out/windows-x86 --config Release --prefix out/package-x86

cmake --preset windows-x64
cmake --build --preset windows-x64 --parallel 2
ctest --preset windows-x64
cmake --install out/windows-x64 --config Release --prefix out/package-x64
```

wxWidgets и JSON-библиотека загружаются только **при конфигурации сборки** из
закреплённых архивов с проверкой SHA-256. Для сборки без сети можно передать
`FETCHCONTENT_SOURCE_DIR_NLOHMANN_JSON` и `FETCHCONTENT_SOURCE_DIR_WXWIDGETS`
с заранее проверенными распакованными исходниками. Архив wxWidgets должен
включать сторонние библиотеки; простой git checkout без submodules недостаточен.

## Linux и отдельное ядро

Нужны GCC с C++17, CMake >= 3.24, Ninja, GTK3 development packages.
На Ubuntu: `sudo apt-get install libgtk-3-dev ninja-build xvfb`.

```sh
cmake -S native -B native/out/linux -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build native/out/linux --parallel 2
ctest --test-dir native/out/linux --output-on-failure
native/out/linux/minstall-native --list
```

`-DMINSTALL_BUILD_GUI=OFF` отключает только GUI и зависимость от GTK/wxWidgets.
Ядро и CLI собираются отдельно. GUI smoke test на Linux регистрируется при
наличии `xvfb-run`; Windows запускает его непосредственно. CI Linux устанавливает
Xvfb, проверяет покрытие собственного `native/src/` (минимум 40%) и отдельно
прогоняет ядро/CLI с ASan/UBSan. Предупреждения компилятора собственного кода
считаются ошибками.

## Запуск и границы контракта

```powershell
.\minstall-native.exe --version
.\minstall-native.exe --list
.\minstall-native.exe --list --catalog "D:\Мой каталог\programs.json"
.\minstall-native.exe --catalog "D:\Мой каталог\programs.json"
```

Без режима открывается GUI. По умолчанию файл ищется **рядом с исполняемым
файлом**, независимо от текущего каталога. `--catalog` — явное переопределение.
При сборке/установке рядом копируется текущий репозиторный каталог. Встроенного
fallback-каталога пока нет. Для Windows используется Unicode `wmain`, пути
`std::filesystem` и UTF-8 в stdout; консольная кодировка восстанавливается.
Исполняемый файл использует console subsystem, поэтому при запуске GUI двойным
щелчком возможно дополнительное консольное окно — это ограничение прототипа.

| Контракт Python | Поведение прототипа |
| --- | --- |
| `--version` | Собственная версия Native 0.1.0 с указанием базы Python 2.2.2; каталог не читается |
| `--list` | Категории/названия/версии в исходном порядке; **все** записи каталога |
| Проверка установленного ПО и фильтр ОС | Не перенесены; статус явно «не проверен», а не «не установлено» |
| Код 0 | Успешная информационная команда или закрытие GUI |
| Код 3 | Ошибка аргументов, конфигурации, чтения или недоступный GUI |
| Коды 1/2 для установки/отмены | Зарезервированы будущим переносом; установки нет |
| `--install`, профили, `--json`, остальные ключи | Отклоняются с кодом 3, без побочных действий |
| Пустой объект `categories` | Допустим для чтения/GUI; `--list` возвращает 3, как Python для пустого каталога |

Это начальное подмножество CLI, не полная замена автоматизации Python.
Служебный `--gui-smoke` открывает окно, проверяет число узлов и выбор первой
программы, затем закрывает его. Он не выполняет установку и нужен для CI/VM.

## Политика чтения JSON

Проверяются обязательные поля схемы, типы всех известных полей, `os`, SHA-256,
границы `retry`/`timeout`, элементы `depends_on`, поля `detect`. `_version`
должен равняться 2. Неизвестные поля разрешены, как в текущей схеме. `url.format`
остаётся аннотацией JSON Schema; URL не используется. Это реализация текущего
контракта, а не универсальный движок JSON Schema: изменения корневой схемы
требуют синхронного обновления валидатора и тестов.

Защитные ограничения: 8 MiB на файл и фактически прочитанные байты, глубина 64,
64 KiB на строку, 4096 членов объекта, 100000 событий парсера. Повторяющиеся
ключи, NUL, некорректный UTF-8, незавершённый JSON, комментарии и хвостовой мусор
отклоняются. Нулевые байты проверяются во всём файле **до** JSON-парсера, в том
числе после корректного документа: парсер может принять NUL за конец ввода.
Экранированный `\u0000` также отклоняется в строках и ключах после декодирования.
UTF-8 BOM принимается. ASCII-управляющие символы экранируются при
выводе каталога в терминал. Диагностика не включает фрагменты JSON и команды.

В отличие от Python-загрузчика, который пропускает отдельные неверные записи,
прототип отклоняет **весь** повреждённый каталог: частичный список не показывается.
Проверка формата не делает команды доверенными — следующий этап исполнения
потребует отдельной модели доверия и проверки Windows-команд.

## Совместимость и следующий этап

Подробности toolset/CRT/SDK и обязательная матрица VM находятся в
[WINDOWS_COMPATIBILITY.md](WINDOWS_COMPATIBILITY.md). Зелёный CI на Windows
Server 2022 не подтверждает запуск на Windows 7/8/10/11. Пакеты PR предназначены
для испытаний, а не для стабильного автообновления. Никакие теги релиза не создаются.

Следующий этап: испытать эти пакеты на целевых VM, затем отдельно переносить
фильтры платформ, обнаружение ПО, профили и зависимости. HTTPS, процессы,
состояние и обновлятор из исходного плана намеренно не входят в этот PR.
