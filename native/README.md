# MInstAll Native — первый прототип

Изолированный перенос на **C++17 + wxWidgets 3.2.11**, версия прототипа **0.1.0**.
Источник контрактов — Python v2.2.2 (`915dfcc7f454`) и существующий
`programs.schema.json`. Учтён документ `MInstAll_CPP_wxWidgets_Migration_Plan.docx`
от 10 октября 2026 года: независимое ядро, постепенный перенос, отдельные сборки,
сохранение Python и проверка готовых бинарников до заявления о совместимости.

## Что работает

- CMake/CTest, отдельное ядро без wxWidgets и окно с деревом категорий/программ.
- Строка меню как в Python: «Файл», «Настройки», «Профили», «Справка».
  Работают пересканирование (`F5`), слежение с интервалом 3/10/30/60 секунд
  или его отключение, инструкция по добавлению файлов, «О программе» (`F1`)
  и выход (`Ctrl+Q`). Интервал действует до закрытия окна; по умолчанию 3 секунды.
  Остальные пункты исходного меню видимы, но неактивны: установка,
  языки, профили, лог и обновления.
  Фиксированные параметры сканирования показаны отмеченными в обычном режиме.
- «Добавить программу» (`Ctrl+N`) выбирает один настоящий установочный файл
  и необязательную категорию-подпапку, копирует файл в `software/` и сразу
  выбирает его в дереве. Исходник сохраняется, существующие файлы не заменяются.
  Копирование показывает прогресс и допускает отмену.
- «Изменить сведения» (`Ctrl+E`) и двойной щелчок по программе открывают редактор
  названия, версии и многострочного описания. Изменения видны сразу и сохраняются
  после перезапуска; «Отмена» ничего не записывает. Без выбранной программы
  команда неактивна. Полный редактор полей Python пока не перенесён.
- «Сохранить каталог» (`Ctrl+S`) выгружает список в выбранный UTF-8 JSON версии 2.
  Перед экспортом обычный список пересканируется; при `--catalog` сохраняется
  открытый снимок, включая дополнительные поля программ и корня JSON.
  Имя по умолчанию — `programs-export.json`; замена существующего файла требует
  отдельного подтверждения. Установочные файлы в экспорт не включаются.
- По умолчанию список строится только по установочным файлам в `software/`
  рядом с исполняемым файлом. Без файлов список и категории пустые; окно
  объясняет, куда добавить программы. Примеры из Python не подставляются.
  GUI по умолчанию проверяет папку каждые 3 секунды: добавленные файлы появляются, удалённые
  исчезают; выбор сохраняется, если соответствующий файл остался на месте.
- Явное чтение UTF-8 `programs.json` через `--catalog`, сохранение порядка и всех полей
  записей, включая неизвестные расширения. Выбор программы показывает название,
  версию и описание обычным текстом. Если версия или описание отсутствует, это
  явно указано. Команды, пути значков и внутренние поля JSON в панели не выводятся;
  URL не открываются, значки не загружаются.
- Проверка установленного ПО показывает статус и установленную версию справа.
  В Windows читаются записи удаления HKLM/HKCU в обоих представлениях реестра.
  `F6` обновляет сведения; кеш включён по умолчанию, действует до 60 секунд
  при очередном обновлении списка и не сохраняется после закрытия окна.
- `--version`, `--list`, `--help`, `--catalog FILE`, `--list --check-installed`.
- Проверки формата, повреждённых файлов, Unicode-путей, CLI и цикла открытия/
  закрытия GUI. Отдельные Windows x86/x64 пакеты в артефактах PR.

Нет исполнения `cmd`, `pre_cmd`, `post_cmd`, `uninstall_cmd`, установки,
скачивания, повышения прав, обновления, записи профилей или
состояния. Стабильные Python-файлы, `build.yml`, `release.yml`, `version.json`
и релиз v2.2.2 не изменяются. Прототип не заменяет `MInstAll_x86.exe`/
`MInstAll_x64.exe`; его имя — `minstall-native.exe`.

## Сборка Windows

На современной машине сборки установите Visual Studio 2022 с компонентами
MSVC v142 x86/x64 **14.29.30133** и Windows SDK **10.0.19041.0**, CMake **3.31.6**.
Presets намеренно требуют этот toolset: при его отсутствии следует установить
его, а не незаметно переключаться на последний компилятор.

Из каталога `native/`:

```powershell
cmake --preset windows-x86
cmake --build --preset windows-x86 --parallel 2
ctest --preset windows-x86
cmake --install out/windows-x86 --config Release --prefix out/package-x86

cmake --preset windows-x64
cmake --build --preset windows-x64 --parallel 2
ctest --preset windows-x64
cmake --install out/windows-x64 --config Release --prefix out/package-x64
```

wxWidgets и JSON-библиотека загружаются только **при конфигурации сборки** из
закреплённых архивов с проверкой SHA-256. Для сборки без сети можно передать
`FETCHCONTENT_SOURCE_DIR_NLOHMANN_JSON` и `FETCHCONTENT_SOURCE_DIR_WXWIDGETS`
с заранее проверенными распакованными исходниками. Архив wxWidgets должен
включать сторонние библиотеки; простой git checkout без submodules недостаточен.

## Linux и отдельное ядро

Нужны GCC с C++17, CMake >= 3.24, Ninja, GTK3 development packages.
На Ubuntu: `sudo apt-get install libgtk-3-dev ninja-build xvfb`.

```sh
cmake -S native -B native/out/linux -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build native/out/linux --parallel 2
ctest --test-dir native/out/linux --output-on-failure
native/out/linux/minstall-native --list
```

`-DMINSTALL_BUILD_GUI=OFF` отключает только GUI и зависимость от GTK/wxWidgets.
Ядро и CLI собираются отдельно. GUI smoke test на Linux регистрируется при
наличии `xvfb-run`; Windows запускает его непосредственно. CI Linux устанавливает
Xvfb, проверяет покрытие собственного `native/src/` (минимум 40%) и отдельно
прогоняет ядро/CLI с ASan/UBSan. Предупреждения компилятора собственного кода
считаются ошибками.

## Запуск и границы контракта

```powershell
.\minstall-native.exe --version
.\minstall-native.exe --list
.\minstall-native.exe --list --check-installed
.\minstall-native.exe --list --catalog "D:\Мой каталог\programs.json"
.\minstall-native.exe --catalog "D:\Мой каталог\programs.json"
```

Без режима открывается GUI. По умолчанию сканируется `software/` **рядом с
исполняемым файлом**, независимо от текущего каталога. Отсутствующая папка —
нормальный пустой список. Сам запуск не создаёт её и не записывает JSON;
запись происходит только при подтверждённом добавлении файла, сохранении сведений
или экспорте каталога.
Примерный `programs.json` из репозитория не копируется в сборку/пакет; даже
если старый файл остался рядом с EXE, автоматически он не читается.
`--catalog FILE` явно включает отдельный режим просмотра всех записей JSON,
без сканирования папки и автоматического обновления; пункты пересканирования
и слежения, добавление файлов и редактор сведений в этом режиме неактивны. Экспорт доступен.
Для Windows используется Unicode `wmain`, пути
`std::filesystem` и UTF-8 в stdout; консольная кодировка восстанавливается.
Исполняемый файл использует console subsystem, поэтому при запуске GUI двойным
щелчком возможно дополнительное консольное окно — это ограничение прототипа.

| Контракт Python | Поведение прототипа |
| --- | --- |
| `--version` | Собственная версия Native 0.1.0 с указанием базы Python 2.2.2; каталог не читается |
| `--list` | Обнаруженные файлы из `software/`; с явным `--catalog` — все записи JSON в исходном порядке |
| Проверка установленного ПО | GUI и `--list --check-installed`: Windows-реестр, явные пути, .NET Framework; неподдерживаемая/неполная проверка даёт «неизвестно» |
| Применимость ОС | Определяется по `os` или расширению файла/команды; запись остаётся в списке с пометкой «для другой ОС» |
| Код 0 | Успешная информационная команда или закрытие GUI |
| Код 3 | Ошибка аргументов, конфигурации, чтения или недоступный GUI |
| Коды 1/2 для установки/отмены | Зарезервированы будущим переносом; установки нет |
| `--install`, профили, `--json`, остальные ключи | Отклоняются с кодом 3, без побочных действий |
| Пустой список | Нормальное начальное состояние; `--list` возвращает 0, stdout пустой, в stderr итог 0 |

Это начальное подмножество CLI, не полная замена автоматизации Python.
Служебный `--gui-smoke` открывает окно, проверяет число узлов и выбор первой
программы, затем закрывает его. Он не выполняет установку и нужен для CI/VM.
CTest отдельно проверяет пустое окно и явно переданный пример JSON.
GUI smoke также проверяет четыре раздела меню, доступность команд для выбранного
режима и события остановки/возобновления слежения, ручного сканирования, проверки ПО и кеша.
Закрытие окна с выбранной программой проверяет отключение обработчиков дерева
до уничтожения меню/дочерних окон; это устраняет падение wxMSW на заполненном дереве.

### Обнаружение файлов

Поддерживаются те же расширения, что у сканера Python: `.exe`, `.msi`, `.bat`,
`.cmd`, `.ps1`, `.reg`, `.sh`, `.bash`, `.deb`, `.appimage`, без учёта регистра.
Читаются только имена и типы файлов; содержимое не запускается и не проверяется
на пригодность для установки. Подпапки образуют категории с разделителем ` / `,
файлы в корне попадают в «ПРОЧЕЕ». Пустые подпапки не показываются. Имена папок
сохраняются, название программы — имя файла без расширения. Эвристики Python
для названий/версий и словарь категорий пока не перенесены; ключи установки не
угадываются. Сохранённые пользователем название, версия и описание заменяют
значения сканера только для найденного файла.

Порядок детерминирован по UTF-8 именам. Глубина — не более 8 подпапок; ссылки
не обходятся, в Windows исключаются также junction/reparse points. Ограничение —
10 000 просмотренных элементов, включая неподдерживаемые файлы и папки.
Превышение лимита или ошибка доступа отклоняет скан целиком. При ошибке
повторного скана GUI очищает прежний список; при включённом слежении повторяет
попытку автоматически, при выключенном доступна ручная проверка `F5`.
Наблюдение пока использует периодический обход на потоке GUI; большие или
медленные сетевые папки могут задерживать интерфейс.

### Добавление и сохранение

Категория в диалоге добавления — одно имя подпапки; пустая строка означает
корень `software/` и раздел «ПРОЧЕЕ». Пути, `..`, управляющие символы и
зарезервированные имена Windows отклоняются. Папка создаётся только при
подтверждённом добавлении. Ссылки/reparse points не используются как источник
или папка назначения. Совпадающий файл уже в нужной папке не копируется повторно.

Копирование выполняется по блокам, с проверкой размера и времени изменения
источника. Временный файл имеет расширение `.tmp` и не попадает в список.
Отмена/ошибка удаляет временные данные; пустая созданная подпапка может остаться.
Завершённый файл публикуется без перезаписи, в том числе при одновременном
появлении одноимённого файла. Во время диалогов/копирования таймер приостановлен,
после закрытия его прежний режим восстанавливается. Файлы не исполняются.

Экспорт сначала сериализуется и проверяется тем же строгим валидатором, затем
пишется во временный файл рядом с назначением. Только полная запись заменяет
выбранный файл атомарной операцией; повреждённый или незаписанный JSON не
подменяет старый. Ссылки и папки заменять нельзя. Это не обещание сохранности
при отключении питания. В POSIX для публикации без замены нужны hard links;
на файловой системе без их поддержки операция завершится ошибкой, без перезаписи.
В Windows используются операции перемещения в пределах того же тома.

Экспорт — снимок списка, не готовый сценарий установки: сканер не создаёт
команды/ключи запуска. Экспортированный JSON не подгружается автоматически.
Файл сведений нельзя выбрать как назначение экспорта через GUI.

### Сохранённые сведения о программах

Редактор создаёт `program-metadata.json` рядом с исполняемым файлом. Формат —
каталог версии 2 с маркером `_kind: "minstall-program-metadata-v1"`; каждая запись
имеет уникальный строковый `source_path`. Путь сопоставляется буквально в UTF-8,
относительно `software/`, с разделителем `/`. Файл сведений не заменяет сканирование:
из него применяются только `name`, `version`, `desc`, без переноса категорий, команд,
URL или других полей. Пути из метаданных не открываются и не исполняются.

Удалённый установщик и пустая категория исчезают, даже если сведения о них
сохранены. При возвращении файла с тем же относительным путём сведения снова
применяются; переименование или перемещение создаёт новую привязку. Совпадение
основано на пути, не на содержимом файла. Автоматического переноса записей из
Python `programs.json` нет. `--list` использует те же сведения; `--catalog` их игнорирует.

Название обязательно, версия и описание могут быть пустыми. Ограничения UTF-8:
название 1024 байта, версия 256 байт, описание 64 КиБ. Переносы строк и табуляция
разрешены только в описании. При сохранении повторно проверяются наличие файла
и неизменность снимка метаданных с открытия редактора. Изменения из другого окна
не затираются; нужно закрыть и снова открыть редактор. Остальные записи и
неизвестные поля сохранённого файла остаются на месте.

Запись использует проверку и атомарную публикацию JSON, как экспорт.
`program-metadata.json.lock` исключает одновременную запись из других окон MInstAll;
блокировка не распространяется на внешние текстовые редакторы. После аварийного
завершения папка блокировки может остаться: удалять её вручную можно только после
закрытия всех окон MInstAll. Ошибка записи не заменяет прежние сведения.
Ссылки/reparse points, дубли путей и повреждённые метаданные отклоняются.
GUI показывает причину ошибки и позволяет повторить чтение через `F5`, включая
ошибку при запуске; частичный список не показывается, повреждённый файл не затирается.

## Проверка установленного ПО

Список по-прежнему создаётся только из файлов `software/` или явно выбранного
JSON. Снимок установленного ПО не добавляет в него программы и не записывается
в каталог, экспорт или метаданные. Обычный `--list` сохраняет прежний формат;
`--list --check-installed` добавляет `installed`, `missing`, `unknown` или
`not-applicable`, установленную версию и признак `outdated` при надёжном сравнении.

В GUI «Не обнаружена» означает отсутствие совпадающей регистрации/явного пути,
а не гарантию отсутствия программы: portable-приложения могут не иметь записи
удаления, а название установщика может отличаться от названия продукта.
Сопоставление консервативное: нормализованное полное имя, затем известный суффикс
версии/архитектуры; произвольная подстрока не используется. Общее название
установщика следует изменить в редакторе на зарегистрированное название продукта.
Кириллица и распространённые Unicode-имена поддерживаются без ANSI-преобразования;
полное Unicode case folding пока не реализовано.

В явном JSON поддержаны `detect.registry_name`, `detect.path`,
`detect.min_version`, `detect.always_runnable`, `detect.net_framework_release`.
Приоритет как в Python: always_runnable, .NET, путь, имя реестра. Всегда доступные
сценарии не считаются установленными. Относительный путь считается от папки EXE;
переменные окружения разворачиваются без запуска команд. Неразрешённые переменные
и ошибки доступа оставляют статус неизвестным. Минимальная версия сравнивается
только для числовых версий; разные наблюдаемые версии оставляют версию неизвестной,
а неполный снимок не объявляет продукт устаревшим.

Реестр читается только для просмотра, без повышения прав: HKLM/HKCU, 32/64-bit
представления, DisplayName/DisplayVersion. Ограничения: 20 000 записей, 8 MiB
строк снимка, 64 KiB на значение. Недоступные/повреждённые данные дают неполный
снимок: найденная программа остаётся установленной, ненайденная — неизвестной.
Linux package-manager detection пока не перенесён; явные пути работают, остальные
проверки остаются неизвестными. Фильтр не удаляет записи другой ОС из списка.

`F6` принудительно перечитывает сведения в обоих режимах; в обычном режиме также
пересканируется software. С отключённым кешем проверка повторяется при каждом
обновлении списка. В явном JSON и при выключенном слежении автоматического таймера
проверки нет; для обновления используйте F6. Проверка выполняется на потоке GUI;
медленные пути/реестр могут задержать окно. Это не движок установки.

## Политика чтения JSON

Проверяются обязательные поля схемы, типы всех известных полей, `os`, SHA-256,
границы `retry`/`timeout`, элементы `depends_on`, поля `detect`. `_version`
должен равняться 2. Неизвестные поля разрешены, как в текущей схеме. `url.format`
остаётся аннотацией JSON Schema; URL не используется. Это реализация текущего
контракта, а не универсальный движок JSON Schema: изменения корневой схемы
требуют синхронного обновления валидатора и тестов.

Защитные ограничения: 8 MiB на файл и фактически прочитанные байты, глубина 64,
64 KiB на строку, 4096 членов объекта, 100000 событий парсера. Повторяющиеся
ключи, NUL, некорректный UTF-8, незавершённый JSON, комментарии и хвостовой мусор
отклоняются. Нулевые байты проверяются во всём файле **до** JSON-парсера, в том
числе после корректного документа: парсер может принять NUL за конец ввода.
Экранированный `\u0000` также отклоняется в строках и ключах после декодирования.
UTF-8 BOM принимается. ASCII-управляющие символы экранируются при
выводе каталога в терминал. Диагностика не включает фрагменты JSON и команды.

В отличие от Python-загрузчика, который пропускает отдельные неверные записи,
прототип отклоняет **весь** повреждённый каталог: частичный список не показывается.
Проверка формата не делает команды доверенными — следующий этап исполнения
потребует отдельной модели доверия и проверки Windows-команд.

## Совместимость и следующий этап

Подробности toolset/CRT/SDK и обязательная матрица VM находятся в
[WINDOWS_COMPATIBILITY.md](WINDOWS_COMPATIBILITY.md). Зелёный CI на Windows
Server 2022 не подтверждает запуск на Windows 7/8/10/11. Пакеты PR предназначены
для испытаний, а не для стабильного автообновления. Никакие теги релиза не создаются.

Следующий этап: испытать эти пакеты на целевых VM, затем отдельно переносить
полные фильтры, Linux-обнаружение ПО, профили и зависимости. HTTPS, процессы,
состояние и обновлятор из исходного плана намеренно не входят в этот PR.
